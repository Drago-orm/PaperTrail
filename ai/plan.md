# 研迹 PaperTrail：按需读取的开发入口

> 先读本页，再读当前状态和指定步骤卡；不要展开所有链接。详细规格、历史过程和其他步骤不是每轮必读内容。

## 固定定位

- 应用根目录：`E:\project\chuanzhi\ai`；下面的应用命令均从这里执行。
- Git 根目录：父目录 `E:\project\chuanzhi`，分支 `main`，远端 `origin`：`https://github.com/Drago-orm/PaperTrail.git`。复用现有仓库，不嵌套初始化。
- 产品：计算机/AI 论文入库、证据化精读/核查、写作分析、可追溯 Idea、MD/DOCX 导出、重复候选和版本管理；范围见按需规格。
- 状态唯一摘要：[docs/current.md](docs/current.md)；规格：[docs/spec.md](docs/spec.md)；历史：[docs/progress.md](docs/progress.md)。

## 读取规则

1. **新对话或上下文恢复**：读本页、`docs/current.md`、用户指定的一张步骤卡。按摘要定位下一步，再核对相关未提交改动及正在执行的任务；延续已有工作，不重复开工或重做已完成步骤。
2. **同一对话继续**：保留已读规则，只读取新步骤卡或发生变化的相关段落。任务中断后先核对工作区，不默认重新通读计划或整套代码。
3. **查代码**：先用 `rg` 定位符号、接口或文件，再读相关函数及必要调用方。仅在正确性确实依赖更多上下文时扩大范围，不机械限制必要阅读。
4. **查资料**：步骤卡标明的规格段落按需读；依赖 API 不确定时只查对应官方文档。锁文件、长日志、论文全文、历史对话和所有步骤不整批输出给模型。
5. **避免重复**：已经获取且未变化的信息复用；成功命令只保留命令、结果和关键警告。只有新改动、失败或新疑点才重读、重跑。
6. **控制范围**：每轮一个可验收步骤。开发默认单个编程 Agent；只有用户要求或存在明确收益的独立工作时才并行，委派只带必要文件和任务信息。

## 共用实现约束

- 一套前端、一套后端、SQLite、本地文件；沿用现有版本、类型、组件和脚本。不重建项目、不做无关重构，不加入空模块、重复依赖或自建框架。
- 代码保持可读、类型严格、错误明确；不得用禁用检查、吞错或假成功换取通过。模型密钥留在后端，上传文件和运行数据不进 Git。
- 精读、写作、核查、Idea 共用客户端/检索/结构化类型；解析、导出和去重计算使用普通程序。作者事实、系统判断与研究设想分开；关键结论有原文依据，未报告不补造。
- 证据绑定文件版本；人工修订不被重跑覆盖；合并可撤销；Idea 不承诺新颖性；不同评估条件不强行比较数值。
- 自动化测试使用固定样例/受控响应，真实模型冒烟另记；回放显著标注。只为关键边界写有价值的测试，静态文案和纯样式不加镜像测试。

## 检查：按影响范围执行一次

| 本步变更 | 收尾检查 |
|---|---|
| 只有 Markdown/文档 | UTF-8、链接、围栏和差异检查；不构建应用 |
| 仅前端 | `.\scripts\check.ps1 -Scope frontend` |
| 仅后端 | `.\scripts\check.ps1 -Scope backend` |
| 两端、共享接口或集成行为 | `.\scripts\check.ps1 -Scope all`；按影响验证关键流程 |

- 调试先跑失败用例或受影响测试；收尾执行所需范围检查。成功后没有新代码改动，不为了写记录、commit 或 push 再跑一次。
- 仅启动/配置/接口联动受影响时做实际启动冒烟；干净安装、路径压力、全流程复现集中在对应步骤和最终交付，不在每步重复。
- 依赖首次安装、确有缺失或锁文件变更才使用 `-Install`；不反复重装。日常冻结检查不改锁，后端使用 `uv run --locked`。uv 不在 PATH 时复用已有脚本的 `.tools/bin/uv.exe` 回退。
- 构建通过不能代替业务验证；证据坐标、核查、人工版本、合并撤销和导出一致性保留各步骤的关键验收。必要测试失败必须修复，不用“节省用量”跳过。

## 每步收尾 G：保留提交与推送

1. 开始时一次检查 Git 状态，按任务确认当前分支/远端；相同会话且配置未变无需反复探查。保留无关改动，不默认 `git add .`。
2. 完成上表和步骤卡要求的检查，检查本步差异及冗余，只暂存本步明确文件；暂存后运行 `git diff --cached --check`。
3. 覆盖更新 `docs/current.md` 的完成步骤、下一步、关键入口、最近检查和阻塞；历史进度只加简短条目。保存真实对话/录屏，不让 AI 重写长篇“开发实录”，不补造历史。
4. 一个步骤创建真实提交，再推送当前分支；成功后核验远端分支包含本提交。提交/推送信息来自执行结果，不为记录自身哈希产生额外循环提交。
5. 推送失败保存本地提交，明确报告“未上传”；针对实际错误修复，不强推、不创建未指定仓库，不把后续步骤批量积压。
6. 推送成功后停止。最终仅报告完成内容、检查结果、提交哈希、上传状态和必要限制；不粘贴源码/整份计划。

```text
执行步骤 NN。应用目录入口是 plan.md，Git 根目录入口是 ai/plan.md；后续文档路径均以应用目录为基准。
首次/上下文恢复时只读入口、docs/current.md 和对应步骤卡；已经加载且未变化的规则不重复读取。

遵守入口的检查矩阵和收尾 G，复用成功检查结果，完成本步 commit、push、远端核验后停止。
简要报告结果；不要全文读取全部规格、历史日志、其他步骤或输出完整源码。
```

已在应用根目录时入口是 `plan.md`；从 Git 根目录启动时入口是 `ai/plan.md`。`NN` 替换为实际步骤，例如 `03`；不需要每轮粘贴共用 Prompt 再粘贴整份计划。

失败修复：保留当前上下文，只读失败输出和受影响代码，定位根因做最小修改；先重跑失败检查，再补必要范围检查，按 G 收尾。不重新规划项目或重复已完成流程。
