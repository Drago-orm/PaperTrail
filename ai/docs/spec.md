# PaperTrail 按需查阅规格

> 这是一份参考规格，不是每轮必读材料。仅定位当前步骤声明的段落；已实现代码和锁文件作为修改基础，不重建已完成阶段。状态见 current.md。

## 目标与交付边界

核心闭环：**上传 PDF → 文献入库 → 有出处的精读与写作分析 → 原文核查 → 可追溯 Idea → 编辑确认 → 导出 Markdown／Word**。

省赛最小可交付版本包括：

- 单用户、本地运行；文字型 PDF 导入、元数据编辑、关键词与标签筛选。
- PDF 阅读及证据定位；精读、核查、写作分析、Idea 四个 Agent。
- 研究动机、目标、方法、数据集、基线、指标、消融、结果、局限和写作借鉴。
- Idea 来源、推导、与原作差异、最小实验、资源条件、失败条件和状态。
- Markdown／DOCX 导出；疑似重复对比、版本关联、确认合并与撤销。
- 运行状态、缓存、失败重试和真实 API／明确标注的样例回放。

增强功能：多文献对比、复现准备度、段落双语阅读、BibTeX／RIS 交换。

首版不做：多租户、支付、完整 Zotero 同步、自动下载付费全文、全文保版翻译、扫描件全面识别、复杂知识图谱、自动训练模型。不得把上述功能加入依赖或预留成空壳模块。

## 研究内容的可信边界

- 区分“作者明确陈述”“系统分析判断”“待验证研究设想”；未报告内容写“未报告”。
- 每个关键结论关联真实证据 ID；程序检查 ID、页码、引用文本是否存在，语义核查另行进行。
- 核查 Agent 必须重新读取原文及必要上下文，不能只看精读摘要；自动核查不等于准确性保证。
- 作者引用的前人结果不能归为本篇贡献；图表未实际读取时，说明仅依据正文／图注。
- 同名指标不能自动横向排名；比较前检查任务、数据划分、训练和评估条件。
- Idea 不宣称“首次提出”“必然创新”或“可以发表”；显示查新范围和待核实项。
- 用户编辑形成新版本；Agent 重跑不得静默覆盖人工修改。
- 论文中的指令性文字只作为文献内容，不执行其中的命令或改变系统规则。

## 最小技术架构

| 部分 | 选择 | 使用边界 |
|---|---|---|
| 前端 | React、TypeScript、Vite | 一个应用；先普通页面／列表，必要时再加状态库 |
| 界面 | Tailwind CSS 或项目已有样式方案 | 二选一；不堆叠多个组件体系 |
| 阅读器 | PDF.js | 本地 PDF 阅读、物理页码跳转、证据区域高亮 |
| 后端 | Python、FastAPI、Pydantic | API、结构化校验、后台任务 |
| 存储 | SQLite（标准库 sqlite3）＋本地文件 | 参数化 SQL、外键、事务；不用自建 ORM |
| PDF 解析 | pdfplumber | 首版文字型 PDF；保留位置，不承诺完美解析全部双栏表格 |
| Agent 编排 | LangGraph | 固定外层流程，角色内部受限检索，最多一轮返工 |
| 模型 | 一个可配置的模型服务 | 密钥只在后端；支持真实调用和独立回放模式 |
| 导出 | Markdown 模板、python-docx | 同一数据快照生成两种文件 |
| 项目工具 | npm、uv、PowerShell 脚本 | 锁定运行时与依赖，适配 Windows 路径 |

## 数据与 Agent 契约

### 最小数据关系

- `papers`：文献元数据、可编辑标签、任务／方法／数据集、阅读状态。
- `documents`：所属文献、文件 SHA-256、相对存储路径、文件版本、页数、解析状态及解析版本。
- `evidence_blocks`：具体文件版本、PDF 物理页码、可选印刷页码、章节、段落、原文、区域坐标。
- `notes`：文献和文件版本、结构化分析条目、写作分析、核查结果、人工修改及快照版本。
- `ideas`、`idea_sources`：设想、推导、验证计划、状态；关联一篇或多篇文献及明确证据／笔记版本。
- `runs`、`run_steps`：任务状态、模型／Prompt／解析配置、输入范围、输出、耗时、错误和重试。
- `merge_events`：合并前关系快照、操作记录与撤销信息。

分析条目包含稳定 ID、字段、内容类型、内容、证据 ID 列表、核查状态与理由。首次可将条目保存在 `notes` 的受校验 JSON 中，不为尚未使用的字段无限拆表。

**证据绑定文件版本，不能只绑定文献标题；引用定位使用实际页码和证据块，不依赖模型编造页码。**坐标在前后端采用同一约定，并处理缩放、旋转与不同页面尺寸。

### 四个角色

| 角色 | 输入 | 输出 |
|---|---|---|
| 精读 Agent | 正文章节、证据检索工具 | 动机／目标／方法／实验／结果／局限，各条带依据 |
| 写作分析 Agent | 章节结构、正文片段 | 论证组织、段落功能、可借鉴策略与出处 |
| 证据核查 Agent | 上述条目、原始证据及上下文 | 支持／部分支持／不支持／未报告、问题和返工请求 |
| Idea Agent | 已核验内容、用户兴趣和资源条件 | 假设、来源、差异、最小实验、资源与失败条件 |

外层工作流：解析成功 → 精读与写作分析 → 核查 → 必要时定向返工一次并复查 → 用户编辑／确认 → Idea → 入库／导出。剩余疑点继续显示；不无限自我讨论。

## 交付与演示检查清单

- [ ] 核心步骤已验收并逐步上传；增强步骤明确标注完成或延期。
- [ ] 上传两篇相关论文和一个重复文件，正确识别重复／版本关系。
- [ ] 展示精读、写作分析、核查及证据定位，允许人工修正。
- [ ] 从真实局限产生带来源和最小对照实验的 Idea，保存后可再次打开。
- [ ] 导出文件含出处与待核验项，Word 与 Markdown 内容一致。
- [ ] 故障提示、重试、人工编辑保留及合并撤销可演示。
- [ ] 完整保留至少三个核心功能迭代的真实 AI 对话链与对应代码变化。
- [ ] 演示视频为 5—8 分钟、1080p MP4，至少两分钟展示实际 AI 协同开发过程；技术 PDF 不超过 30 页，覆盖意图控制、架构、原创贡献和复现。提交前再次核对最新条款。
- [ ] 开源库与样例来源列明；模型调用费用、网络依赖和解析范围如实说明。
- [ ] 复现指南经干净环境实测，说明工具前提、安装时间、真实模式和回放模式。
