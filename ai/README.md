# 研迹 PaperTrail

面向计算机／AI 实验型论文的本地研读工具。当前实现步骤 01—08：文献库、证据阅读、精读／写作／核查／Idea 四角色流程，以及可追溯的 Idea 库、验证计划和人工版本。导出尚未实现。

项目根目录是本文件所在的 `ai/`；Git 仓库位于父目录。所有命令在项目根目录用 PowerShell 7 执行。

## 环境与安装

本步实际使用 Node.js **24.11.1**、npm **11.6.2**、Python **3.14.3**、uv **0.13.8**。前端版本文件和 `package.json`、后端 `.python-version` 和 `pyproject.toml` 固定运行环境及依赖；提交两个包管理器实际生成的锁文件。

先安装以上 Node/Python 版本。若 PATH 中没有 uv，可在项目内安装工具：

```powershell
python -m pip install --target .tools uv==0.13.8
```

脚本优先使用 PATH 中的 uv，否则使用 `.tools/bin/uv.exe`；该工具目录不提交。

首次安装或依赖有变更时执行冻结安装及检查：

```powershell
.\scripts\check.ps1 -Scope all -Install
```

日常检查不改锁文件：

```powershell
.\scripts\check.ps1 -Scope frontend
.\scripts\check.ps1 -Scope backend
.\scripts\check.ps1 -Scope all
```

前端执行 `npm run build`，包含 TypeScript 检查和 Vite 生产构建。后端执行 `uv run --locked python -m compileall -q app` 和 `uv run --locked python -m pytest -q`，测试包含应用导入与健康接口。任一步失败均返回非零退出码。

## 启动与配置

```powershell
.\scripts\start.ps1
```

固定地址：前端 [http://127.0.0.1:5173/](http://127.0.0.1:5173/)，后端健康接口 [http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health)。Vite 将同源 `/api` 请求代理到后端；服务仅绑定本机，不开放额外跨域来源。

脚本拒绝占用端口，先用 `uv sync --locked` 核对后端环境，再直接启动虚拟环境 Python；健康接口和页面真实就绪后报告启动成功。按 Ctrl+C 停止；一个服务退出时也会清理本次启动的另一服务及其子进程。运行日志在被忽略的 `data/logs/`，失败时检查对应日志。

无需模型配置也可启动。可将 `.env.example` 复制为 `.env`，填写 `PAPERTRAIL_MODEL_BASE_URL`、`PAPERTRAIL_MODEL_NAME` 和 `PAPERTRAIL_MODEL_API_KEY` 后重启。已有环境变量优先。基址必须是无凭据的绝对 HTTP(S) URL，程序追加 `/chat/completions`，例如 `https://api.openai.com/v1`。阿里云工作空间兼容基址以 `/compatible-mode/v1` 结尾，按[官方地域与基址说明](https://help.aliyun.com/en/model-studio/regions/)填写。`.env` 被 Git 忽略；不要把密钥写入前端或提交。

留空和非法 URL 明确显示，真实精读返回配置错误；健康接口只检查配置格式，不代表服务连接成功，也不返回密钥。服务是否可用以实际任务结果为准。

后续范围见 [plan.md](plan.md)，实际检查和开发证据见 [docs/progress.md](docs/progress.md)。

## 数据与文件

启动时初始化 `data/papertrail.sqlite3`，用 `PRAGMA user_version` 依序执行事务迁移；版本不支持或初始化失败会阻止启动。每个连接启用外键，写入使用参数绑定和事务。数据库及文件都被 Git 忽略；测试注入临时数据目录，不修改已有文献数据。

模型覆盖文献、文档版本、证据块、笔记快照、Idea 及来源、运行与阶段、合并事件。笔记用 Pydantic 校验的 JSON 保存条目与核查状态，人工修订插入新快照并保留父版本；证据和笔记来源绑定具体文件版本。存储检查结构、证据存在性与文件归属；语义支持判断由下述核查操作单独执行。坐标约定为物理页从 1 开始、左上角原点、PDF 点坐标，边界受页面宽高约束；阅读器按下述 viewport 约定投影。

确定性服务接口位于 `backend/app/db.py`（`create_paper`、`create_note`）和 `backend/app/services/storage.py`（`store_document`、`document_path`）。文件由服务器 UUID 保存为 `data/documents/<UUID>.pdf`，原文件名仅为元数据；按文档 ID 查数据库后读取，并检查实际路径未越出数据目录。记录真实 SHA-256 和递增版本，失败时回滚并清理本次写入。

底层存储只保存字节并初始化为 `pending`；通过以下上传接口才会执行 PDF 检查和解析。

## PDF 上传与解析

`POST /api/documents` 接收 multipart 的 `file`，可选 `paper_id`。在后端 [API 文档](http://127.0.0.1:8000/docs) 操作；真实文件限制 20 MiB、200 页。按文件签名及 pdfplumber 打开结果检查实际格式，不信任 MIME 和文件名。错误格式返回 415、大小超限返回 413；解析失败仍保存文档 ID，`document.parse_status` 和 `report.status` 为 `failed`，附错误原因。

`GET /api/documents/{document_id}` 返回持久化报告和证据。报告包含解析器版本、物理页数、实际提取页列表、警告和标题/作者候选（缺失为 null），不自动覆盖元数据。同 SHA-256 重传复用原文献/文档与证据 ID；原先仅存储的文件可在重传时解析。

按视觉文字行生成段落候选，保存真实原文、章节候选、物理页和坐标。检测到双栏/复杂布局、旋转页时跳过并警告；空白、扫描、损坏及加密文件明确失败或受限，不执行 OCR。含图表页仅读取文字，报告 limited。即使 parsed 也仅表示文字提取完成，不保证通用版式阅读顺序或图表准确性；完整覆盖以 report 为准，数据库 parsed 可能带限制。论文中的指令文字只保存为原文。

固定自制、CC0 样例生成器在 `backend/tests/test_pdf_import.py`，涵盖单栏、双栏、图像页、空文本、旋转和坐标。第三方论文全文不随仓库提交。

## 文献库与阅读器

网页上传后直接显示入库文献。题目、作者、摘要、关键词、标签、阅读状态可编辑保存；数组字段每行一项，标题/作者候选需用户采用并保存。关键词筛选是文本匹配，多个条件按 AND 组合，不是语义检索。

单条移除将该文献放入移除区，可选择恢复；原文件、证据和来源仍保留。文件版本可切换，点击原文证据会跳转物理页并高亮。阅读器支持缩放、旋转、手动页码和原文件链接；坐标先按原页面 viewport 转为 PDF 坐标，再投影至当前 viewport，不把设备像素倍率重复乘进 CSS。

接口：GET /api/papers（q/title/author/abstract/keyword/tag/reading_status/removed）；PATCH /api/papers/{UUID} 编辑元数据；PUT /api/papers/{UUID}/visibility?removed=true 或 false；GET /api/documents/{UUID}/file 按文档 ID 读取 PDF。数据库顺序迁移至 v3，新增 removed 标记。解析限制仍以步骤03报告为准。

运行 frontend/ 中的 npm run test:reader，使用 fixtures/reader.pdf 的 CC0 双尺寸样例，验证真实 PDF.js 的缩放与旋转坐标。PDF.js 6.5.438 使用本地 worker，依赖及锁文件由 npm 实际生成。构建保留 PDF.js 带来的体积告警，不调高阈值隐藏。

## 结构化精读与笔记

选择文档后可运行真实 API 或固定样例回放。真实调用会将所选范围的文字发送给后端配置的模型服务；回放明确标注“未调用模型”，只接受 `fixtures/reader.pdf` 的固定哈希，不代表真实论文效果。笔记每个版本保存来源，人工修订继承原版来源；旧数据来源未知时不补造。

章节候选和关键词均按文字匹配，按物理页顺序最多选 40 个证据块、16000 字符，最后一块可截断。这不是全文搜索式总结。任务保存实际证据 ID、页码、字符数、解析版本、Prompt 版本、阶段、错误、耗时和服务报告的用量。没有用量时显示“服务未报告，费用未知”；不根据耗时估算账单。一个本地工作线程，最多 10 个活动任务，同一文档不能重复排队；服务重启将中断任务标为失败，不伪造恢复成功。当前按单后端进程启动。

共享客户端使用 OpenAI 兼容 Chat Completions 和 JSON 输出模式，单次网络 I/O 超时 60 秒，每个角色调用最多两次请求，仅连接失败、超时、429 和指定 5xx 重试一次；精读任务最多两次请求，单独核查含返工最多六次，完整流程的分批与恢复上限见下文。输出最多 4096 tokens、响应最多 256 KiB。需要服务支持这些接口参数，HTTP 错误、截断、非法结构或引用不实均明确失败，不保存为成功笔记。失败请求也可能产生费用，只有服务实际返回的用量能被记录。

精读覆盖动机、目标、方法、数据集、基线、指标、消融、结果和局限九项。Pydantic 检查结构，程序检查证据 ID 和逐字引用存在；作者陈述与系统判断分开。缺失项写“未报告”，仅指本次输入范围。精读结果初始待语义核查；解析跳过的双栏、旋转页或图表不会被模型补齐。论文文字作为不可信内容传入，不执行其中指令。

每次成功运行追加分析快照；人工保存追加新版本，保留父快照，不覆盖旧笔记。编辑中刷新或重跑不会自动替换草稿；基版已有更新时保存返回 409 并保留编辑，需先查看新版本。只有实际编辑过的条目重置为待核查。引用按钮复用阅读器按证据 ID 跳页和高亮。

接口：POST/GET `/api/documents/{UUID}/reading-runs`，GET `/api/reading-runs/{UUID}`，GET/POST `/api/documents/{UUID}/notes`。POST 精读接收 `mode`（live/replay）、可选 `section` 和 `query`；保存笔记接收 `base_note_id` 和条目 ID 到文本的 `changes`。数据库 v4 增加笔记来源；旧 v3 笔记迁移为 unknown，保留原内容。

## 原文核查与受控返工

在最新已保存笔记上点击“核查此版本（真实 API）”。核查会重新从数据库读取该文件版本的原始证据，优先保留完整的被引证据，再取同页相邻段落和有界剩余文字，最多 40 块／16000 字符；被引原文本身超限则明确失败。条目限 1—14 条（精读9项、写作5项）、正文总长最多 16000 字符。原文、条目和指令性文字都作为不可信数据，不执行其中命令。

模型逐条给出支持、部分支持、不支持、本次范围未报告或仍待核查，并说明理由。数值核查同时考虑单位、任务、数据集／划分、指标、评估条件和比较对象。程序另行校验证据 ID 和逐字引文；模型判断不能替代准确性保证，不输出无依据的置信度或准确率。页面显示当前状态、理由、初查／复查历史、实际范围、耗时和已返回的用量；用量缺失或重试时明确提示统计可能不全。

机器生成笔记可选一次定向返工：只传入问题条目，再重新读取原文复查这些条目；已支持条目不重跑，仍不确定的保留。整个核查任务最多初查、返工、复查三个角色调用，每个最多两次请求，不递归。人工修订只核查，不自动改写；编辑中的文字显示“尚未核查”，须先保存。结果追加新快照，原版保留；核查期间已有人工新版本时任务失败并保留核查记录，绝不覆盖。返工／复查失败也保留此前记录，不把未复查的修订保存成已核查笔记。

`POST /api/documents/{UUID}/verification-runs` 接收 `base_note_id` 和可选 `revise`（默认 true，人工版强制 false）；沿用已有任务查询接口。数据库 v5 用 `notes.verification_run_id` 关联核查记录，旧笔记为空，不补造历史。`source_mode` 表示初始精读来源，核查记录另行标注，避免将回放派生版本当成未调用模型的新结果。

`fixtures/verification-cases.json` 是 CC0 自制注入错误和正确／缺失对照，**不是历史模型错误或真实论文**。测试用现有 PDF 生成器构造原文；受控响应仅验证编排、边界和失败处理。实际模型验收的通过项和服务限制见 [开发记录](docs/development/step-06.md)，不能把受控结果算作模型检出率。

## 写作分析与研读流程

点击“运行精读→写作→核查→Idea”，使用相同的章节／关键词范围和可选兴趣、资源条件。写作分析输出问题引入、贡献组织、方法说明、实验安排、局限讨论五项；每条解释原段落的组织方式、可迁移策略及适用边界，绑定逐字短引文，不大段仿写。缺失项仍为本次范围“未报告”，原文存在性与语义核查分开。

调度使用锁定的 LangGraph 1.2.22，按[官方 Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)串接四个固定节点，沿用本地单工作线程。每个成功节点立即保存结果和 `run_steps` 检查点，失败时页面显示节点、错误、已完成结果及原输入；服务重启后点击“重试失败节点（沿用原输入）”恢复一次，成功节点复用。没有已支持来源时 Idea 节点明确失败，前三个角色结果仍保留。页面轮询展示阶段状态与结果，不展示模型思维过程。

流程核查每批最多7项，写作条目和精读条目一起核查；最多一轮问题条目返工，复查也分批。四角色正常一轮最多16次请求，含一次失败节点恢复的硬预算最多26次；按节点预留上限，中断无法确认的调用仍占预算。旧三角色流程沿用原范围与预算，不自动接入 Idea。已知请求数和已返回用量单独记录，中断期间数量未知时不会填0；费用不能按已返回用量视为完整账单。较大输入仍可能超时，已完成角色结果保留。

缓存位于现有 `run_steps`，键是节点角色与规范化输入的 SHA-256，包含文件哈希／解析版本、所选原文及证据ID、Prompt版本与内容摘要、模型基址／模型名／凭据摘要、笔记／核查快照、兴趣和资源条件。只保存键，不保存模型凭据。输入、人工修订或条件变化使相关结果不能命中旧缓存；恢复沿用原输入，模型配置变化需启动新流程。缓存引用缺失会明确失败。

精读、写作均可人工编辑保存。已有人工内容在流程重跑中保留，缺失的部分可补生成；人工版只核查，不自动改写。并发新版本会阻止旧节点写入和旧流程恢复。核查子任务与父流程分开记录，父流程在子任务提交后中断也可复用结果，避免重复生成快照。

`POST /api/documents/{UUID}/workflow-runs` 接收 `section`、`query`、`interest`、`resources`、`revise`，以及默认 true 的 `include_idea`；仅支持 live。`include_idea=false`保留三角色范围。`POST /api/workflow-runs/{UUID}/retry` 恢复失败流程。沿用任务／笔记查询接口，主任务列表不混入子任务；状态和缓存复用现有任务记录。真实调用与浏览器验证记录见 [步骤07](docs/development/step-07.md)及[步骤08](docs/development/step-08.md)。

## 可追溯 Idea 库

从侧栏“Idea 库”或流程结果链接进入。可根据研究问题／假设文本、状态筛选，新增人工 Idea、根据所选来源生成、编辑或切换历史版本；状态为草稿、用户确认、验证中、归档。用户确认是工作记录，不代表已证实新颖性或效果。生成和编辑均保存不可变快照，列表显示每组最新版本；重跑创建新草稿或显著标注缓存复用，人工版本保留。

来源最多6个条目、3个文件，只接受作者陈述／系统判断中状态为“支持”的条目，且须与成功核查任务的快照逐字一致。部分支持、未报告、未核查或研究设想不作为生成事实。界面区分只读来源内容和可编辑假设，保留初始精读的真实／回放标记；缺少旧来源记录时明确提示。每条来源保存具体文件、笔记、条目和证据 ID，原文总计最多40块／16000字符，来源条目正文最多12000字符。

生成内容包含研究问题、待验证假设、推导、与原作的拟议差异、最小实验、资源、失败条件、新颖性待核实问题。没有执行外部查新，不承诺首次创新、效果提升或发表价值。结构化实验要求两组使用同一模型、数据集和划分，列出相同设置项，仅 `changed_factor` 对应的值不同，指标与评估协议共用；待确认条件单独列出。这检查计划结构，不证明因果设计充分，也不表示实验已执行。

“定位来源原文”复用 PDF 阅读器，按具体文件和证据跳物理页、高亮，同时显示来源笔记版本及原内容。软移除文献后来源保留、原文件仍可查看；不能用新版本或模型文字替换旧来源。

独立 Idea 任务最多两次模型请求，输入为所选支持条目、真实原文、兴趣与算力／数据条件。缓存包含这些快照、文件哈希／解析版本、模型／Prompt 配置、当前笔记版本以及相关 Idea 人工修订记录；人工修订或条件变化使相关缓存失效。Idea 子任务提交后父流程中断时也可恢复并复用结果。

接口：GET `/api/idea-sources` 列出最新笔记中的可用条目；POST `/api/idea-runs` 传入 `sources:[{note_id,item_id}]`、`interest`、`resources`，沿用任务查询。GET `/api/ideas?q=&status=`、GET `/api/ideas/{UUID}`、GET `/api/ideas/{UUID}/versions`；POST `/api/ideas` 用 `draft`、`status`、可选 `base_idea_id` 新增或修订，旧基版冲突返回409并保留编辑。模型不能设置确认状态。

数据库v6为已有Idea表增加根版本、父版本、人工修订标记、生成任务和结构化实验，来源表增加条目ID；未新增依赖。旧记录保留原文字计划，缺少结构化实验或生成来源时明确显示未记录，不补造历史。测试中的合成来源、受控响应和真实调用分开记录，不能作为通用科学评测。

## Markdown 与 Word 导出

在笔记版本旁点击“准备导出此笔记版本”，或在 Idea 库勾选最多10个已保存版本，再下载 Markdown／Word。Idea 编辑区也可导出当前历史版本。未保存编辑须先保存；筛选和新修订不会将已勾选的旧版本替换成最新版本，可清空后重选。

一次准备在同一数据库事务中捕获指定版本及当时的元数据、来源和解析报告，再由同一内容序列生成两种文件。导出不调用模型、不重新解析PDF，不要求配置模型。文件含快照ID／时间／内容SHA256；再次下载读取已保存文件，之后的编辑不会改变它们。修改元数据后需要重新准备导出。

文件保留精读／写作条目、作者陈述／系统判断／待验证设想标签、核查状态与理由、人工修订、版本和任务溯源；Idea包含原文字计划、两组设置表、指标、评估协议和待确认条件。离线出处提供论文元数据、原文件名／版本／SHA256、具体笔记／条目／证据ID、物理页、章节候选、坐标及保存原文和引文，无需依赖本地网页链接。覆盖报告和受限警告照实保留；旧记录缺少来源、结构化计划或任务时明确提示，不补造。自动核查和设想的原有限制继续有效。

接口：POST `/api/exports` 传 `{note_id:UUID}` 或 `{idea_ids:[UUID,...]}`，返回同一快照的 `markdown_url` 和 `word_url`；GET `/api/exports/{UUID}/md` 或 `/docx` 下载。空选择／重复／混选返回422，版本缺失404，无法表示的控制字符或损坏文件409，文件I/O失败500。只在两种文件及快照全部写好后发布完成清单，下载校验文件哈希，写入失败清理本次残片。

输出保存在忽略的 `data/exports/{UUID}/`，导出本身不修改数据库结构（当前数据库版本见下节）。文件持续保留，不自动过期；无需保留的快照可在停用下载后手动删除对应目录。使用锁定的 [python-docx 1.2.0](https://python-docx.readthedocs.io/en/latest/) 及其传递依赖lxml生成Word，生成本身无需安装Office；A4、少量标题样式、固定表宽、重复表头及自然分页。实际Microsoft Word打开／PDF渲染和浏览器验收见[步骤09记录](docs/development/step-09.md)，其他文档阅读器未逐一验收。

## 去重、版本关联与可撤销合并

选择文献后，在“去重与版本关联”查看候选、并排比较全部可选元数据和附件，也可手动选择其他文献比较。上方增加可编辑DOI和出版年份，未知留空；年份要求四位整数，DOI仅做匹配形态检查，不查询注册机构、不推断缺失字段。同SHA256上传复用原文件版本，页面明确提示；旧数据若已有同哈希附件，比较时显示字节相同的依据。

候选使用题目NFKC／大小写／标点空白规范化、DOI前缀／大小写规范化及完整作者姓名匹配。题目相同或有效形态DOI相同产生候选；题目前512个规范化字符的序列匹配系数≥0.85，或≥0.65且同名作者、填写年份相差不超过1，也产生候选。页面给出依据和缺失／差异，不把系数当成重复概率；摘要保留原文并排供人工核对，不调用模型，也不据标题相似认定同研究。

优先选择“关联为同研究不同版本”，预印本和正式版的两个条目／文件都保留。“相关但不同文献”与“非重复”也是人工关系标记；非重复默认不再列出，可勾选显示并清除标记。误判不导致删除。关系绑定原始条目ID，合并后的对比仍可看到原条目的已有关系。

只有点击“确认合并到左侧主条目”并确认后，才采用表格中逐字段选择的左／右值。合并只更新主条目元数据、在文献库汇总展示两侧附件；右侧条目保留并隐藏于列表，原文献／文档／笔记／证据／Idea来源ID、原文件哈希和文件版本均不迁移或重新编号。合并后的多个原文件可以各自为v1，版本选择器同时显示原归属，比较面板可查看完整ID和哈希。隐藏条目需先撤销才能编辑元数据／移除；主条目移除时汇总组的Idea可选来源随之隐藏，已有出处仍保留。

合并和撤销均在事务中执行。比较响应包含快照token，元数据、附件、来源计数或关系变化后旧请求返回409，要求重新比较。合并记录保存前态及原始笔记／Idea关系快照；撤销仅还原合并实际改变且仍等于合并后值的字段、解除汇总关系，保留其余后续编辑、新附件、新笔记和新Idea。字段冲突明确拒绝，不强制覆盖；同主条目的多次合并须倒序撤销。当前按独立右侧条目逐个汇入左侧主条目，不直接嵌套合并两个已有汇总组；先撤销右侧的合并再操作。旧记录缺少可安全撤销的前态时也会明确拒绝。

撤销时当前附件仍按原文档ID阅读；若恢复的归属在另一可见分组，页面跟随切换，保留该附件上尚未保存的笔记编辑。导出增加DOI／年份和当时汇总主条目ID，原出处仍指向原文件版本；已保存的旧导出文件不受合并或撤销影响。

接口：GET `/api/papers/{UUID}/duplicates?include_distinct=false`、GET `/api/paper-comparison?left_id=UUID&right_id=UUID`；PUT `/api/paper-relations` 传 `left_id/right_id/token/kind`（kind为version、related、distinct，null清除）；POST `/api/merges` 传相同配对与token、`fields:{字段:left或right}`；GET `/api/papers/{UUID}/merges`；POST `/api/merges/{UUID}/undo`。不存在404，过期比较／字段或顺序冲突409，结构无效422。

数据库v7增加DOI／年份、原始文献关系表和汇总归属视图，复用既有merge_events，不添加依赖。测试覆盖同文件、题目变体、版本关联、相似题目不同研究、非重复纠正、旧版本迁移、事务失败回滚、合并后新增Idea／附件／人工笔记、冲突与倒序撤销；受控浏览器验收见[步骤10记录](docs/development/step-10.md)。规则会漏报或误报，最终关系与合并由用户判断。

## 多文献比较与复现准备清单

从侧栏“多文献比较”选择2—5篇文献，明确每列的原文件与已保存笔记版本；默认选最新已保存版本，可切换旧版，未保存的笔记编辑须先在文献库保存。无笔记时明确提示并禁止生成；同一文献或已合并组不能重复计作多篇。用户标记为同研究不同版本的条目会另行提示，不作为独立研究或独立重复实验。

矩阵沿用笔记的任务／目标（goal）、方法、数据集、基线、指标、消融和局限。每个纳入的条目必须有属于该文件版本、与保存原文逐字匹配的引文，显示原有作者陈述／系统判断、人工修订、来源模式和核查状态。未报告、不支持、研究设想或无有效引文的内容不填成对比结论，留空并提示；未核查和部分支持的主张继续显著标记，不提升为已确认事实。点击出处复用阅读器，跳原PDF物理页与证据区域；快照保存文件名／版本／SHA256、原文献／文件／笔记／证据ID、原文和坐标，解析覆盖／警告／错误如实保留。

配置线索从现有有界检索范围中识别明确的“标签：值”，不重新解析PDF或调用模型。每篇最多40个证据块、16000字符，被引原文优先；截短的相邻块不自动识别为完整配置。标签支持任务／Task、数据集／Dataset、数据划分／Data split／Dataset split、指标／Metric、评估协议／Evaluation protocol、代码／Code／Source code、数据获取／Data availability／Data access、依赖／Dependencies、环境／Environment、参数／Parameters／Hyperparameters、训练配置／Training configuration／Training config、推理配置／Inference configuration／Inference config、硬件／Hardware。只匹配独立标签行，复杂自然语言或未识别格式不推断。

可在每列补充人工摘录，选择原文段落、填写逐字引文及其中的值；服务器校验证据归属、引文和摘录值，拒绝改写、跨文件证据或补造。每列每字段最多一条，共最多12条；补充不覆盖已识别的其他设置，出现多套值仍提示歧义。人工摘录未生成快照前仅留在当前页面；切换文件／笔记前会确认清空。

可比条件覆盖任务、数据集、划分、指标定义／单位、评估协议及训练／推理配置。只有两侧均有单一明确线索才比较文字；仅归一空白，保留大小写、数值、符号和单位，不把mJ与MJ合并。不同值提示不能强行比较指标；缺失、多套设置或可用性表述冲突时为未知。即使全部摘录文字一致，仍要求人工核对完整协议、单位和未摘录条件，不自动排名或判定研究可比。

复现清单列出代码、数据获取、依赖／环境、参数、训练配置、推理配置、硬件。未识别项的值为null并提示“本次有限范围未识别”，不宣称全文未报告；明确“未提供／不可用”的摘录保留出处、值留空。其他原文或人工摘录只作为待核实线索，不代表资源可访问或实验已就绪，不计算就绪率／成功率，不抓取外链、安装依赖或执行代码。

POST `/api/study-comparisons` 传 `{studies:[{note_id:UUID,annotations:[{field,value,evidence_id,text}]}]}` 生成冻结快照，annotations可省略，字段名为task、dataset、split、metric、protocol、code、data、dependencies、parameters、training、inference、hardware。GET `/api/study-comparisons/{UUID}` 重开；页面链接为 `#compare/{UUID}`。不存在404，证据／重复文献组／快照完整性异常409，结构／数量／无效摘录值422，文件读写错误500。

快照及内容SHA256保存在忽略的 `data/comparisons/{UUID}.json`，写临时文件再原子发布，失败不返回成功。之后的元数据、笔记、合并或输入选择不自动改动旧快照；真实后端重启也可按链接重开。文件持续保留，无自动过期；数据库仍v7，模型角色、依赖及锁文件未变。本步受控自制样例验证出处、差异、缺失和保存行为，不代表真实论文自动分析或复现质量；记录见[步骤11](docs/development/step-11.md)。
